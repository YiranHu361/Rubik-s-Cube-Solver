# 3x3 Rubik's Cube solver (Kociemba two-phase)

A from-scratch C++ implementation of Herbert Kociemba's two-phase algorithm,
a JavaScript port that runs in the browser, and a web app that reconstructs a
real cube from two photos and animates the solution.

```
src/Cube.h, Cube.cpp       cubie-level cube model, moves, facelet strings, validation
src/Coords.h, Coords.cpp   the six coordinates and their move tables
src/Pruning.h, Pruning.cpp five pruning tables (breadth-first search over coordinate pairs)
src/Solver.h, Solver.cpp   the two-phase IDA* search with six probes
src/main.cpp               command line: solve, scramble, bench, vectors
tests/tests.cpp            unit tests (make test)
web/                       the browser app and its JavaScript solver (see below)
```

## Build and run

Run `make` from inside this folder (the Makefile uses relative paths).

```
make                      # builds bin/cube3
make test                 # builds and runs the unit tests (about 4.8 million checks)
./bin/cube3 solve DUUBULDBFRBFRRULLLBRDFFFBLURDBFDFDRFRULBLUFDURRBLBDUDL
./bin/cube3 solve <facelets> --time 100     # keep improving for 100 ms
./bin/cube3 scramble --seed 7               # a random cube and a scramble that makes it
./bin/cube3 bench 1000                      # first-solution benchmark
./bin/cube3 bench 1000 --time 100           # time-budget benchmark
./bin/cube3 vectors 200 --stop 21           # cross-check data for the JavaScript port
```

A cube is given as a 54-character string in Kociemba's facelet order: the
U, R, F, D, L and B faces, 9 stickers each, read row by row as you look at
the face with U on top (for U itself, B is at the top of the picture; for D,
F is at the top). Each character names the face whose centre has that colour.

## How it works

**Cube model.** A cube is stored as where each of the 8 corners and 12 edges
sits and how it is twisted or flipped (`CubieCube`). A move is itself such a
cube, and applying a move is multiplying two permutations. The six basic move
tables were typed in by hand, so `tests.cpp` cross-checks every move against
a separate implementation that moves stickers around a facelet string purely
geometrically.

**Phase 1** brings the cube into the subgroup G1 generated by U, D, R2, L2,
F2 and B2. A cube is in G1 exactly when three small numbers are all zero:
the corner twist (3^7 = 2187 values), the edge flip (2^11 = 2048 values) and
which 4 of the 12 edge positions hold the middle-slice edges (495 values).
Move tables give the next value of each number for each of the 18 moves, so
the search never touches the full cube.

**Phase 2** finishes inside G1 with the 10 phase-2 moves, using the corner
permutation (40320), the permutation of the 8 U/D edges (40320) and the
permutation of the 4 slice edges (24).

**Pruning tables.** For a pair of coordinates, a table stores the exact number
of moves needed to zero that pair (breadth-first search from the solved
state). The real cube needs at least that many, so IDA* cuts any branch whose
remaining depth is smaller. Five tables are used: slice x twist, slice x flip,
twist x flip for phase 1, and slice-permutation x corner-permutation,
slice-permutation x U/D-edge-permutation for phase 2.

**Search.** Iterative deepening over the phase-1 length; every phase-1
solution starts a bounded phase-2 search, and the bound shrinks each time a
shorter total is found. Phase 2 is capped at 11 moves because phase 1 has
thousands of solutions and moving on to the next one is cheaper than
finishing a long phase 2 (measured: cap 18 gave 22.5 moves in 4.7 ms, cap 11
gave 20.5 moves in 3.7 ms on 300 cubes). The solver also searches six
"probes" in turn: the cube seen from three axes (via whole-cube rotations of
the facelet string) and the inverse of each. Any probe's solution translates
back to the original cube.

## Benchmark

1000 random cubes (uniformly random reachable states), `make bench`, on an
Intel Xeon 2.10 GHz cloud VM, g++ -O2, single thread. Table construction
(about 0.6 s) is excluded.

| mode                          | average length | longest | average time |
|-------------------------------|---------------:|--------:|-------------:|
| first solution found          | 20.52 moves    | 22      | 3.2 ms       |
| keep improving for 100 ms     | 19.29 moves    | 21      | 100 ms       |

## Tests

`make test` runs about 4.8 million checks: facelet round trips, every move
against the geometric sticker implementation, group identities
(a * a^-1 = I, (ab)^-1 = b^-1 a^-1), every coordinate value round trip, move
tables against real moves, pruning tables admissible and completely filled,
whole-cube rotations, Kociemba's published example cube (his 19-move solution
solves our parse of his string, so the facelet convention matches), and 200
random cubes solved and verified.
